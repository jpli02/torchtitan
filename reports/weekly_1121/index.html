Terminal-Bench: the learning-rate study

Lowering the learning rate removes the damage of over-training, but it does not raise the test score: every checkpoint that was not over-trained lands in the same narrow band, and the run trained from the base model in one pass solves — of —.

  • The schedule and the 8-bit optimizer behave exactly as configured on the real model; there is no bug.
  • Continuing from v3 at 2e-5 memorizes: epoch 8 fits its new rows almost perfectly (token loss —) while its loss on the test tasks' runs rises to — (v3: —), and it solves — of —.
  • From the base model, 2e-5 is not too high: in one pass every held-out loss was still falling when the run ended.
  • The held-out loss separates over-trained checkpoints from the rest, but not the good ones from each other: the 5e-6 recipe has the best held-out loss and solves — of —.
  • Side finding: the trainer reads its data in file order, and v3's run never reached the skill rows at the end of its file, so v3 is in effect a model of the earlier data. The from-base run shuffles its data.

LiveCodeBench: routers of the released model

The released exit gate sits on the best curve that threshold routers of Ouro-2.6B reach in real execution. Cache repairs recover a little accuracy but none passes the gate, and even an exact cache, which saves no compute, adds only a few problems. All runs below decode the 342 test problems with real early exit and grade them with the official tests.

  • A token that leaves after loop 1 is read correctly, but the copies of its loop-1 keys and values stand in for loops 2–4 of every later token, and once more than about half the tokens leave after loop 1 the answers drift into repetition.
  • The LLM agent's lead over the Gaussian process is timing noise: its evaluations 8, 9 and 10 gave the same answers as its best run on — of 342 problems, yet scored —, — and — from the measured speed alone.
  • Searches from now on count executed loops per token instead of timing them.

Running: BO over the gate's training (gate NAS)

Started on Nov 21, the HumanEval experiment moved to Ouro-2.6B: each evaluation trains an exit gate from a random initialisation with the Stage-II loss while the model stays frozen, then decodes with real early exit. A Gaussian process searches the gate's depth, width, activation, input LayerNorm, the Stage-II gamma and the exit threshold, 25 evaluations per benchmark. Definitions
Executed loops
Recurrence loops actually computed per generated token, counted by the model (1 to 4; full depth = 4). It is the compute measure, unlike measured speed on shared GPUs.
Router and thresholds
A token stops after loop s once the released gate's cumulative exit probability reaches q_s; (q, q, q) is the released gate's single knob.
Copy fill and calibrated fill
A token that stops early leaves empty cache slots for the loops it skipped. The decoder copies its last keys and values into them; the calibrated fill maps them with affine maps fitted by regression instead.
Exact cache
Every loop is still computed and only the readout follows the router, so the cache is exact and nothing is saved: an upper bound for any cache repair.
Sign test
Exact two-sided test on the problems that only one of two runs solves.
